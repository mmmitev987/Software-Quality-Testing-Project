Тестовите ја покриваат страната со листа на рецепти во Mealie (/g/home):
  1. Пребарување по клучен збор преку кутијата за пребарување
  2. Филтрирање по категорија преку паѓачкото мени "Categories"
  3. Филтрирање по ознака (таг) преку паѓачкото мени "Tags"
  4. Копчето "Random" (коцка) — навигација до случаен рецепт
  5. Сортирање по абецеден ред (А → Ш) преку менито "Created/Alphabetical"

Стратегија за тест-податоци:
  beforeAll: преку API се создаваат три рецепти и еден сет на организатори:
    • "e2e AAA Pasta Carbonara"  — доделена категорија "e2e-cat-pasta"
    • "e2e MMM Green Smoothie"   — доделена ознака "e2e-tag-vegan"
    • "e2e ZZZ Beef Stew"        — без категорија/ознака (рецепт за шум)
  Имињата се избрани така AAA < MMM < ZZZ абецедно, за TEST 5.
  На почетокот на beforeAll се бришат евентуални остатоци од претходно
  неуспешно извршување (cleanup-first стратегија).

  afterAll: API ги брише сите три рецепти, категоријата и ознаката.

  beforeEach: се врши логирање и навигација на /g/home.

Важни технички забелешки:
  • Пребарувањето во Mealie користи целотекстно поклопување по зборови
    (full-text OR токени) — пребарување по "e2e AAA Pasta Carbonara" би
    вратило и RECIPE_C (содржи "e2e"). Затоа TEST 1 пребарува по "Carbonara"
    кој постои само во RECIPE_A.
  • Филтрите (Categories, Tags) се паѓачки менија со checkbox-и.
    Менито НЕ се затвора по клик (close-on-content-click="false").
    Потребно е директно кликање на <input type="checkbox"> внатре во
    list-item-от, НЕ само на насловниот текст.
  • По промена на филтер или сортирање, composable-от (watchDebounced)
    чека 500 ms пред да испрати барање — затоа тестовите чекаат 600 ms
    после интеракцијата (waitForTimeout(600)) пред да го проверат резултатот.
  • Мрежното чекање (waitForLoadState('networkidle')) потврдува дека
    барањето за рецепти е завршено пред да се направат тврдењата.

TEST 1 — Дали кутијата за пребарување ги прикажува само рецептите чие
          ime се поклопува со пребарувањето?
────────────────────────────────────────────────────────────────────────────────

  Navigираме на /g/home?search=Carbonara. Composable-от (hydrateSearch)
  го чита параметарот од URL-то при монтирање и веднаш го применува
  филтерот — еквивалентно на тоа корисникот да напише "Carbonara" во
  кутијата за пребарување.

  Тестираме дали:
    • "e2e AAA Pasta Carbonara" е видлив (содржи "Carbonara") ✓
    • "e2e ZZZ Beef Stew" НЕ е видлив (не содржи "Carbonara") ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 2 — Дали филтерот "Categories" ги прикажува само рецептите
          во избраната категорија?
────────────────────────────────────────────────────────────────────────────────

  Кликаме на копчето "Categories" — се отвора паѓачко мени со список.
  Го наоѓаме list-item-от за "e2e-cat-pasta" и кликаме на неговиот
  checkbox (<input type="checkbox"> внатре во .v-list-item).
  Притискаме Escape за затворање на менито.
  Чекаме 600 ms (debounce) + networkidle (fetch).

  Тестираме дали:
    • "e2e AAA Pasta Carbonara" е видлив (ја има категоријата) ✓
    • "e2e ZZZ Beef Stew" НЕ е видлив (нема категорија) ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 3 — Дали филтерот "Tags" ги прикажува само рецептите
          со избраната ознака?
────────────────────────────────────────────────────────────────────────────────

  Ист пристап како TEST 2 — паѓачкото мени "Tags", list-item за
  "e2e-tag-vegan", директен клик на checkbox-от, Escape, debounce чекање.

  Тестираме дали:
    • "e2e MMM Green Smoothie" е видлив (ја има ознаката) ✓
    • "e2e ZZZ Beef Stew" НЕ е видлив (нема ознака) ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 4 — Дали копчето "Random" (коцка) навигира до страна на рецепт?
────────────────────────────────────────────────────────────────────────────────

  Кликаме на копчето со улога "Random" во заглавјето на листата.
  Копчето избира случаен рецепт и навигира на /g/{group}/r/{slug}.

  Тестираме дали:
    • URL-то се менува на /g/{group}/r/{slug} (со regex /\/g\/[\w-]+\/r\/[\w-]+/) ✓
    • URL-то повеќе НЕ е /g/home ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 5 — Дали изборот "Alphabetical" во сортирањето ги подредува
          картите со рецепти по азбучен ред А → Ш?
────────────────────────────────────────────────────────────────────────────────

  Чекор 1: Кликаме на копчето "Created" (активното сортирање) → "Alphabetical".
            Копчето добива натпис "Alphabetical" — потврда дека orderBy=name.
            Стандардниот насок е DESC (Ш→А).
            Чекаме 600 ms (debounce) + networkidle.

  Чекор 2: Кликаме на копчето "Alphabetical" → "Sort Ascending".
            Насокот се менува на ASC (А→Ш).
            Чекаме 600 ms (debounce) + networkidle.

  Чекор 3: Во кутијата за пребарување пишуваме "e2e" (pressSequentially)
            за да ја стесниме листата само на трите тест-рецепти.
            Чекаме 600 ms (debounce) + networkidle.

  Провера на редослед:
    Мрежата со картички може да смести сите три рецепти во ист ред
    (ист Y координат). Затоа не споредуваме Y позиции туку DOM редослед:
    ги читаме сите .v-card-title, наоѓаме индексите на RECIPE_A и RECIPE_C,
    и тврдиме indexA < indexC.

  Тестираме дали:
    • "e2e AAA Pasta Carbonara" е видлив ✓
    • "e2e ZZZ Beef Stew" е видлив ✓
    • DOM индексот на "e2e AAA…" е помал од DOM индексот на "e2e ZZZ…"
      (AAA се јавува пред ZZZ во азбучен ред А→Ш) ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.
