Тестовите ја покриваат страната Meal Planner во Mealie
(/household/mealplan/planner/view + /edit):
  1. Структурна проверка — јазичиња, 7 колони за денови и копчиња
  2. Префрлање помеѓу јазичињата Edit и Meal Planner
  3. Засеаниот рецепт се прикажува во колоната за денешен ден (view режим)
  4. Бришење на запис за оброк во режим за уредување (edit режим)
  5. Копчето "Add All to List" го отвора дијалогот за листа за купување

Стратегија за тест-податоци:
  beforeAll: преку API се создаваат еден рецепт и два записи за оброци:
    • Рецепт: "e2e Steak Dinner" (slug: e2e-steak-dinner)
    • Запис 1: поврзан со рецептот (тип: dinner, датум: денес)
               → се задржува за TEST 3 и TEST 5
    • Запис 2: само белешка "e2e Delete Me" (тип: dinner, датум: денес)
               → се брише во TEST 4
  На почетокот на beforeAll се брише евентуален остаток од претходно
  неуспешно извршување (cleanup-first стратегија).

  afterAll: API ги брише двата записа (Запис 2 веројатно веќе е избришан
            во TEST 4 — 404 одговорот се игнорира) и рецептот.

  beforeEach: се врши логирање и навигација на /household/mealplan/planner/view,
              проследено со waitForLoadState('networkidle').

Важни технички забелешки:

  • Јазичиња (tabs) со рутирање:
    Јазичињата "Meal Planner" и "Edit" се имплементирани со v-tab :to={name}
    (Vue Router навигација), а не со DOM toggle. Кликањето менува URL:
      /household/mealplan/planner/view → /household/mealplan/planner/edit
    Тестовите го потврдуваат URL-то преку waitForURL() по секое кликање.

  • Структурна разлика помеѓу view и edit режим:
    Копчето "Add All to List" во плanner.vue има:
      <BaseButton v-if="route.name === TABS.view" ...>
    Тоа значи дека копчето ПОСТОИ ВО DOM само во view режим. Во edit режим
    е комплетно отстрането (не само скриено). Тестот 2 го користи ова за
    верификација на режимот.

  • Колони за денови (.col-borders):
    view.vue рендерира v-col со class="col-borders" за секој ден.
    Стандардно numberOfDays = 7, па тестот очекува точно 7 колони.
    Секоја нова test страница добива свежа localStorage (без зачувани
    преференции), па секогаш се враќа на стандардот.

  • Бришење на запис (TEST 4):
    Копчето за бришење во edit.vue е:
      <v-btn class="ml-auto" size="small" variant="text" icon @click="...deleteOne">
    Тоа е последното копче во редот .py-2.px-2.d-flex на секој запис.
    Тестот го наоѓа картичката преку .v-card.my-1 + hasText, потоа клика на
    button.ml-auto. По бришењето се чека networkidle и се верификува дека
    текстот "e2e Delete Me" исчезнал.

  • "Add All to List" дијалог (TEST 5):
    Функцијата addAllToList() во planner.vue:
      1. Го повикува getShoppingLists() (API baranje за листи за купување)
      2. Го поставува shoppingListDialog = true (v-model за компонентата)
      3. RecipeDialogAddToShoppingList се монтира (v-if="shoppingLists" стана true)
      4. watch([dialog, ...]) ве компонентата го отвора BaseDialog →
         v-dialog се прикажува (v-overlay.v-dialog.v-overlay--active)
    Тестот чека waitForLoadState('networkidle') (за API повикот) па верифицира
    дека .v-overlay.v-dialog.v-overlay--active е видлив.

  • Две засеани картички за оброци (entryId и deleteEntryId):
    Користиме два различни записи за да избегнеме зависност меѓу тестовите.
    TEST 4 брише само "e2e Delete Me" (Запис 2), додека "e2e Steak Dinner"
    (Запис 1) останува достапен за TEST 5 (за да биде активно копчето
    "Add All to List" — копчето е оневозможено ако нема рецепти во неделата).
