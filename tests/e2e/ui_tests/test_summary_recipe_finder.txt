Тестовите ја покриваат страната Recipe Finder во Mealie
(/g/home/recipes/finder):
  1. Почетна состојба на страната без избрани состојки
  2. Прикажување на чип и предлози кога е избрана состојка
  3. Отстранување на чипот → враќање на почетната состојба
  4. Рецепт со недостасујќа состојка се прикажува во "Almost Ready to Make"
     со чип за недостасувачката состојка
  5. Кликање на чипот за недостасувачка состојка ја додава во "Selected
     Ingredients"

Стратегија за тест-податоци:
  beforeAll: преку API се создаваат две состојки и еден рецепт:
    • Состојка FOOD_A: "e2e-tomato"
    • Состојка FOOD_B: "e2e-basil"
    • Рецепт: "e2e Tomato Basil Pasta" со FOOD_A и FOOD_B поврзани
      преку recipeIngredient (food: { id, name }) — ова овозможува
      Recipe Finder API да ги препознае состојките и да пресмета
      кои недостасуваат при барање на предлози
  На почетокот на beforeAll се бришат евентуални остатоци од претходно
  неуспешно извршување (cleanup-first стратегија).

  afterAll: API ги брише рецептот, FOOD_A и FOOD_B.

  beforeEach: се врши логирање (страната пренасочува на /g/home).
              Секој тест самостојно ракува со навигацијата и localStorage.

Важни технички забелешки:

  • Пронашран проблем со реактивноста на food store:
    Страницата recipe_finder/index.vue содржи линија:
      const foods = foodStore.store.value   (setup-time capture)
    Ова е НЕ-реактивна врска. Asyncronusниот refresh() во useStore
    се извршува ПОСЛЕ setup(), но store.value е заменет (не мутиран),
    па Vue не го повторно рендерира SearchFilter со новата листа.
    Практичниот ефект: паѓачкото мени "Foods" секогаш прикажува
    "No results found" при директен клик веднаш по вчитување на страната.

  • Решение преку localStorage (hydrateFoods):
    Функцијата hydrateFoods() во onMounted ОЧЕКУВА (await) refresh() само
    ако preferences.value.foodIds.length > 0. Затоа тестовите 2–5
    го поставуваат localStorage клучот "recipe-finder-preferences" со
    foodIds: [foodAId] ПРЕД навигацијата. Ова гарантира дека:
    (1) hydrateFoods() го извршува refresh() и ги вчитува состојките,
    (2) selectedFoods е поставен пред state.ready = true,
    (3) SearchFilter доаѓа до рендерирање со веќе поставени состојки.

  • watchDebounced (500 ms) — откако selectedFoods се менува, composable-от
    чека 500 ms пред да го повика API-то за предлози. Тестовите чекаат
    600 ms + networkidle за да бидат сигурни дека предлозите се вчитани.

  • Разлика помеѓу двата типа чипови:
    — Чипови за "Selected Ingredients" → closable, содржат .v-chip__close
    — Чипови за "Missing" состојки → содржат v-checkbox (input[type=checkbox]),
      без .v-chip__close
    Тестовите ги разликуваат преку:
      .v-chip.filter({ has: locator('.v-chip__close') })      — избрани
      .v-chip.filter({ has: locator('input[type="checkbox"]') }) — недостасуваат

  • recipeIngredient структура при PUT на рецепт:
    { note: '', quantity: 1, unit: null,
      food: { id: foodId, name: foodName }, isFood: true, display: '...' }
    Само id и name во food-об'ект се доволни за API-то да го препознае
    поврзувањето и да ги врати предлозите со точно пресметани missingFoods.

  • Проверка на "Almost Ready to Make" vs "Ready to Make":
    — missingFoods.length > 0 || missingTools.length > 0 → missingItems → "Almost Ready"
    — missingFoods.length === 0 && missingTools.length === 0 → readyToMake → "Ready to Make"
    maxMissingFoods стандардно е 20; 1 недостасувачка состојка ≤ 20 → рецептот се прикажува.

TEST 1 — Дали почетната страна прикажува празна состојба со сите контроли?
────────────────────────────────────────────────────────────────────────────────

  Го бришеме localStorage клучот "recipe-finder-preferences" (ако постои),
  потоа навигираме на /g/home/recipes/finder без никакви зачувани состојки.

  Тестираме дали:
    • Насловот "Recipe Finder" (heading h2) е видлив ✓
    • Копчињата Foods, Tools, Other Filters, Settings се видливи ✓
    • Текстот "No ingredients selected" е видлив ✓
    • Текстот "No recipes found" е видлив ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 2 — Дали претходно избраната состојка се прикажува во "Selected
          Ingredients" и ги вчитува предлозите за рецепти?
────────────────────────────────────────────────────────────────────────────────

  Го поставуваме localStorage со foodIds: [foodAId], потоа навигираме.
  hydrateFoods() ги вчитува состојките, selectedFoods = [FOOD_A].
  watchDebounced се активира по 500 ms → API ги враќа предлозите.

  Тестираме дали:
    • Насловот "Selected Ingredients" е видлив ✓
    • Closable чипот за "e2e-tomato" (со .v-chip__close) е видлив ✓
    • "No recipes found" НЕ е видлив (предлозите се вчитани) ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 3 — Дали отстранувањето на чипот ја враќа почетната празна состојба?
────────────────────────────────────────────────────────────────────────────────

  Почнуваме со FOOD_A избрана (преку localStorage + hydrateFoods).
  Кликаме на копчето × (.v-chip__close) на чипот за "e2e-tomato".
  removeFood(food) се повикува → selectedFoods = [] →
  watchDebounced → recipeResponseItems = [] → state.recipesReady = true.

  Тестираме дали:
    • "No ingredients selected" е видлив ✓
    • "No recipes found" е видлив ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 4 — Дали рецепт со недостасувачка состојка се прикажува во
          "Almost Ready to Make" со чип за таа состојка?
────────────────────────────────────────────────────────────────────────────────

  Само FOOD_A е избрана; рецептот бара и FOOD_A и FOOD_B.
  missingFoods = [FOOD_B] → рецептот влегува во секцијата missingItems.

  Тестираме дали:
    • Насловот "Almost Ready to Make" е видлив ✓
    • Насловот на рецептот "e2e Tomato Basil Pasta" е видлив ✓
    • Ознаката "Missing" е видлива ✓
    • Чипот за "e2e-basil" со input[type=checkbox] (без .v-chip__close)
      е видлив — тоа е чипот за недостасувачката состојка ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 5 — Дали кликање на чипот за недостасувачка состојка ја додава
          во "Selected Ingredients"?
────────────────────────────────────────────────────────────────────────────────

  Почнуваме со истата состојба како TEST 4 (само FOOD_A избрана).
  Кликаме на checkbox-от во чипот за "e2e-basil" (missingChip.getByRole('checkbox').click()).
  handleCheckbox() → addFood(FOOD_B) → selectedFoods = [FOOD_A, FOOD_B].

  Тестираме дали:
    • Closable чипот за "e2e-basil" (со .v-chip__close) се прикажува
      во Selected Ingredients ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.
