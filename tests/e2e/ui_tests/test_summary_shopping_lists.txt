Тестовите ги покриваат страните за листи за купување во Mealie
(/shopping-lists и /shopping-lists/{id}):
  1. Структурна проверка на страната со сите листи (index)
  2. Креирање нова листа преку дијалог
  3. Навигација до листата со кликање на картичка
  4. Додавање ставка преку формата на страната на листата
  5. Штиклирање на ставка ја преместува во панелот "Checked Items"

Стратегија за тест-податоци:
  beforeAll: преку API се создаваат една листа и една ставка:
    • Листа: "e2e Shopping List" → зачуван listId
    • Ставка: "e2e check me" (checked=false) на таа листа → зачуван checkItemId
              (зачувана за TEST 5 кој ја штиклира)
  На почетокот на beforeAll се бришат евентуални остатоци од претходно
  неуспешно извршување (cleanup-first стратегија) со помошникот
  deleteListByName() кој ги наоѓа листите по точно совпаѓање на
  името и ги брише преку DELETE /api/households/shopping/lists/{id}.

  afterAll: API ги брише ставката (checkItemId) и листата (listId),
            плус секоја "e2e New List" создадена од TEST 2 преку UI.

  beforeEach: се врши логирање. Секој тест самостојно навигира на
              сопствена почетна URL.

Важни технички забелешки:

  • ?disableRedirect=true на /shopping-lists:
    Кога домаќинството има само 1 листа за купување, Mealie автоматски
    пренасочува на страната на таа листа наместо да го прикаже индексот.
    Query параметарот ?disableRedirect=true го откажува тоа пренасочување.
    Тестовите 1, 2 и 3 го користат за да остане на индексот.

  • Копчето "Create" — строг режим (strict mode):
    Страната рендерира ДВА копчиња со текст "Create":
      1. Во странечката навигација (sidebar) — "+ Create" за нова листа
      2. Во главниот дел (.v-main) — "Create" копчето на индекс страната
    getByRole('button', { name: 'Create' }) би наишло на strict mode
    violation (2 елементи). Решение: getByRole('main').getByRole('button',
    { name: 'Create' }) го стеснува пребарувањето само на главниот регион.

  • .v-overlay--active за копчето "Create" во дијалогот (TEST 2):
    Откако дијалогот се отвора, постојат два "Create" копчиња на страната:
    едното во sidebar-от и едното во дијалогот. page.locator('.v-overlay--active')
    го стеснува пребарувањето само кон содржината на активниот дијалог.

  • span.flex-grow-1 за навигација до листата (TEST 3):
    Картичката (.v-card.left-border) содржи иконски копчиња (уреди, избриши)
    кои имаат @click.prevent — кликањето на нив НЕ навигира. Само
    span.flex-grow-1 (текстот на името на листата) го активира linkTo
    и навигира до /shopping-lists/{id}. Затоа тестот клика специфично
    на тој span, а не на целата картичка.

  • getByRole('combobox', { name: 'Add item' }) наместо getByLabel (TEST 4):
    Vuetify рендерира и input елемент (role=combobox) И "Clear Add item"
    икона копче (aria-label="Clear Add item") — обата го имаат "Add item"
    во нивното достапно ime. getByLabel('Add item') би наишло на
    strict mode violation. getByRole('combobox') ги стеснува само на
    вистинскиот input елемент.

  • deleteListByName() помошник:
    Бидејќи API враќа пагинирани резултати, помошникот праќа GET со
    ?page=1&perPage=100 и потоа ги филтрира client-side по точно
    совпаѓање на name. Ова е безбедно за тест-средини со мал број
    листи. Ако GET повикот врати HTTP грешка, функцијата молчи излегува
    (не го крие вистинскиот неуспех).

  • "One item checked" — i18n плурал (TEST 5):
    ShoppingListPage рендерира expansion панел за штиклирани ставки само
    кога listItems.checked.length > 0. Текстот е i18n множина:
      0 ставки → панелот е скриен
      1 ставка  → "One item checked" (индекс 1 на множинскиот низ)
      N ставки  → "{N} items checked"
    Тестот штиклира точно 1 ставка и го верификува текстот "One item checked".

    • Копчето "Create" во главниот дел (role=main) е видливо ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 2 — Дали креирањето нова листа преку дијалогот ја додава на индексот?
────────────────────────────────────────────────────────────────────────────────

  Кликаме "Create" (скопирано во role=main). Дијалогот "Create Shopping List"
  се отвора. Го пополнуваме полето "New List" со "e2e New List".
  Кликаме "Create" копчето во .v-overlay--active (активниот дијалог).
  POST /api/households/shopping/lists се повикува и листата се создава.

  По networkidle:

  Тестираме дали:
    • Картичката .v-card.left-border со текст "e2e New List" е видлива ✓
      (timeout 10 s за серверскиот одговор и ре-рендерирањето)

  afterAll ја брише "e2e New List" преку deleteListByName().

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 3 — Дали кликањето на картичката навигира до страната на листата?
────────────────────────────────────────────────────────────────────────────────

  Ја наоѓаме картичката .v-card.left-border со текст "e2e Shopping List".
  Кликаме на span.flex-grow-1 (текстот на ime — не на иконските копчиња).
  Vue Router навигира на /shopping-lists/{listId}.

  По networkidle:

  Тестираме дали:
    • Насловот "e2e Shopping List" (role=heading) е видлив ✓
    • Врската "All Lists" (role=link) е видлива — ова е копчето за наzad ✓

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 4 — Дали додавањето ставка преку формата ја прикажува во листата?
────────────────────────────────────────────────────────────────────────────────

  Навигираме директно на /shopping-lists/{listId} (со зачуваниот listId
  од beforeAll — без потреба за навигација преку UI).
  Кликаме на комбо-бокс "Add item" (role=combobox) → уредувачот се отвора.
  Го пополнуваме полето "Note" со "e2e groceries item".
  Кликаме на последното копче во .v-card-actions (копчето Save).
  PUT /api/households/shopping/items се повикува.

  По networkidle:

  Тестираме дали:
    • Текстот "e2e groceries item" е видлив во листата ✓
      (timeout 10 s)

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────
TEST 5 — Дали штиклирањето на ставка ја преместува во Checked Items?
────────────────────────────────────────────────────────────────────────────────

  Засеаната ставка "e2e check me" е претходно внесена преку API (beforeAll)
  со checked=false. Навигираме на /shopping-lists/{listId}.
  Ја наоѓаме редицата .v-row со тој текст, кликаме на .v-checkbox input.
  PUT /api/households/shopping/items/{checkItemId} со checked=true се повикува.

  По networkidle:

  Тестираме дали:
    • Текстот "One item checked" е видлив (expansion панелот се прикажува) ✓
      (timeout 10 s)

  ОЧЕКУВАН РЕЗУЛТАТ: Тестот ПОМИНУВА.
