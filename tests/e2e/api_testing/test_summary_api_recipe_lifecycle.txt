Тестовите се извршуваат строго по ред (test.describe.serial).
Еден корисник се создава пред сите тестови и се брише по завршувањето.


────────────────────────────────────────────────────────────────────────────────
Животен Циклус на Рецепт — Создавање, измена, дуплирање, бришење
────────────────────────────────────────────────────────────────────────────────

TEST 1 — Дали POST /recipes враќа 201 и slug на рецептот?
  Испраќаме POST со поле name.
  Тестираме дали одговорот е 201 и дали вратената вредност е slug (стринг).

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 2 — Дали GET /recipes/{slug} го враќа рецептот со точни полиња?
  Испраќаме GET со slug-от од TEST 1.
  Тестираме дали одговорот е 200 и дали name и id се точни.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 3 — Дали PUT /recipes/{slug} ги зачувува описот и белешките?
  Испраќаме PUT со нов description и notes.
  Тестираме дали одговорот е 200 и дали вредностите се зачувани.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 4 — Дали POST /recipes/{slug}/duplicate создава нов независен рецепт?
  Дуплираме го рецептот.
  Тестираме дали новиот рецепт има различен id и различен slug.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 5 — Дали GET /recipes/{UUID} работи покрај lookup по slug?
  Испраќаме GET со UUID (не со slug) на рецептот.
  Тестираме дали серверот враќа 200 — Mealie поддржува двата формати.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 6 — Дали DELETE /recipes/{slug} враќа 200?
  Бришеме го рецептот.
  Тестираме дали серверот враќа 200.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 7 — Дали GET /recipes/{slug} по бришење враќа 404?
  Испраќаме GET на избришаниот рецепт.
  Тестираме дали серверот враќа 404 Not Found.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 8 — Дали POST со иmе "---" (празен slug) враќа 400?
  Испраќаме POST со name: "---" кое по slugify() станува празен стринг.
  Тестираме дали серверот одбива со 400 Bad Request.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 9 — Дали вториот рецепт со исто иmе автоматски добива "-1" суфикс?
  Создаваме два рецепти со идентично иmе.
  Тестираме дали slug-от на вториот е ист slug + "-1".

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.

────────────────────────────────────────────────────────────────────────────────

TEST 10 — Дали PUT на непостоечки рецепт враќа 404?
  Испраќаме PUT на slug кој не постои во базата.
  Тестираме дали серверот враќа 404 Not Found.

  ОЧЕКУВАН РЕЗУЛТАТ: ПОМИНУВА.
