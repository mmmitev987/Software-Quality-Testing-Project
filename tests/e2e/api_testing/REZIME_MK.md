# Резиме на API Тестирање — Mealie Апликација

**Изработено:** API тестирање на Mealie (self-hosted recipe manager)  
**Технологија:** Playwright (TypeScript) — `request` фиксчер за директни HTTP повици  
**Локација:** `tests/e2e/api_testing/`

---

## Вовед

Меalie е open-source апликација за управување со рецепти. Нејзиниот REST API
е изграден со FastAPI (Python) и е поделен на следните главни домени:

| Домен               | Основни Endpoints                                   |
|---------------------|-----------------------------------------------------|
| Автентикација       | `/api/auth/token`, `/api/auth/refresh`              |
| Корисници           | `/api/users/self`, `/api/users/{id}`                |
| Рецепти             | `/api/recipes`, `/api/recipes/{slug}`               |
| Коментари           | `/api/comments`, `/api/comments/{id}`               |
| Листи за Купување   | `/api/households/shopping/lists`, `.../items`       |
| Организатори        | `/api/organizers/tags`, `/categories`, `/tools`     |
| Администрација      | `/api/admin/users`, `/api/admin/groups`             |

Тестовите се организирани во **7 групи**, инспирирани од GoRest API Testing
документацијата на колегите, со додатоци специфични за Mealie.

## Група 1 — Автентикација (`test_01_authentication.spec.ts`)

**Цел:** Да се провери дека системот за автентикација работи исправно за
сите можни сценарија — правилни акредитиви, погрешни акредитиви и заштита
на ресурсите.

### Тестови:

| Тест | Опис | Очекуван Резултат |
|------|------|-------------------|
| T01 | Пристап до `/users/self` без никаков токен | 401 Unauthorized |
| T02 | Пристап со лажен (генериран) токен | 401 Unauthorized |
| T03 | Логирање со погрешна лозинка | 401 Unauthorized |
| T04 | Логирање со непостоечки корисник | 401 Unauthorized |
| T05 | Логирање со точни акредитиви | 200 + `access_token` |
| T06 | Пристап до `/users/self` со валиден токен | 200 + точни кориснички податоци |
| T07 | Освежување на токенот | 200 + нов `access_token` |
| T08 | Пристап до јавен endpoint без токен | 200 + верзија на апликацијата |
| T09 | Обичен корисник на admin endpoint | 403 Forbidden |

**Техники:** OAuth2 password grant, Bearer token, негативни случаи

## Група 2 — CRUD Синџир за Корисници (`test_02_user_crud_chain.spec.ts`)

**Цел:** Да се провери дека сите операции над корисничкиот ресурс работат
правилно и во точен редослед. Секој тест зависи од претходниот.

### Синџир на тестови:

1. **T01** — Регистрирање нов корисник → 201 + податоци зачувани
2. **T02** — GET на сопствениот профил → 200 + точна е-пошта
3. **T03** — PUT со нова е-пошта и fullName → 200 + промените зачувани
4. **T04** — Втор корисник обидува да го уредува профилот на прв → **403**
5. **T05** — Корисникот обидува себеси да се прогласи admin → **403**
6. **T06** — Admin го брише тест-корисникот → 200
7. **T07** — GET на избришан корисник → **404**

**Техники:** `test.describe.serial()`, споделена состојба, cross-user тестови

## Група 3 — Животен Циклус на Рецепт (`test_03_recipe_lifecycle.spec.ts`)

**Цел:** Да се провери целосниот животен циклус на еден рецепт — создавање,
читање, ажурирање, дуплирање и бришење.

### Синџир на тестови:

1. **T01** — POST `/recipes` → 201 + slug во одговорот
2. **T02** — GET `/recipes/{slug}` → 200 + правилни полиња
3. **T03** — PUT со нов опис и белешки → 200 + промените зачувани
4. **T04** — POST `/recipes/{slug}/duplicate` → 201 + нов независен рецепт
5. **T05** — GET по UUID (не само по slug) → 200
6. **T06** — DELETE → 200
7. **T07** — GET после бришење → **404**
8. **T08** — POST со "---" (невалиден slug) → **400**
9. **T09** — Два рецепти со исто иmе → вториот добива "-1" суфикс
10. **T10** — PUT на непостоечки рецепт → **404**

**Специфики на Mealie:** Автоматска slug генерација, UUID lookup, дуплирање

## Група 4 — CRUD Синџир за Коментари (`test_04_comments_chain.spec.ts`)

**Цел:** Да се провери дека коментарниот систем функционира правилно,
вклучувајќи заштита на туѓи коментари.

### Синџир на тестови:

1. **T01** — POST `/comments` со recipeId и текст → 201
2. **T02** — GET `/comments/{id}` → 200 + user объект е вклучен
3. **T03** — GET `/recipes/{slug}/comments` → листата ги содржи нашите
4. **T04** — PUT `/comments/{id}` со нов текст → 200
5. **T05** — Туѓ корисник обидува да брише → **403**
6. **T06** — Сопственикот го брише → 200
7. **T07** — GET после бришење → **404**
8. **T08** — POST без recipeId → **422**
9. **T09** — POST со непостоечки recipeId → 404 или 422

**Инспирација:** GoRest Comments Callbacks Tests

## Група 5 — Листа за Купување (`test_05_shopping_list_chain.spec.ts`)

**Цел:** Да се провери функционалноста специфична за Mealie — управување
со листи за купување и нивните ставки. Нема еквивалент во GoRest.

### Синџир на тестови:

1. **T01** — POST `/households/shopping/lists` → 201 + листа со userId
2. **T02** — GET сите листи → нашата е присутна
3. **T03** — GET поединечна листа → 200 + listItems масива
4. **T04** — PUT со ново иmе → 200 + промената зачувана
5. **T05** — POST `/households/shopping/items` со shoppingListId → 201
6. **T06** — PUT на ставката (checked: true) → 200
7. **T07** — DELETE на ставката → 200
8. **T08** — DELETE на листата → 200
9. **T09** — GET на избришана листа → **404**
10. **T10** — POST без иmе → **422**

## Група 6 — Само Негативни Тестови (`test_06_negative_validation.spec.ts`)

**Цел:** Да се провери дека API-то правилно ги одбива сите невалидни барања
и враќа соодветни HTTP кодови на грешка.

### Тестови по домен:

**Рецепти:**
- N01 — POST без тело → 422
- N02 — POST со "---" (празен slug) → 400
- N03 — GET непостоечки → 404
- N04 — DELETE непостоечки → 404
- N05 — PUT непостоечки → 404

**Корисници:**
- N06 — GET admin/users со непостоечки UUID → 404
- N07 — DELETE со невалиден ID формат → 422 или 404
- N08 — Регистрација со дуплирана е-пошта → 400

**Shopping Lists:**
- N09 — GET непостоечка листа → 404
- N10 — POST item со непостоечки shoppingListId → 404/422

**Коментари:**
- N11 — GET непостоечки коментар → 404
- N12 — PUT непостоечки коментар → 404

**Organizers:**
- N13 — GET непостоечки таг → 404

**Неавторизиран пристап:**
- N14 — POST /recipes без токен → 401
- N15 — DELETE /admin/users без токен → 401

**Инспирација:** GoRest "Only Negative Tests" група

## Група 7 — Крај-до-Крај Синџир (`test_07_end_to_end_chain.spec.ts`)

**Цел:** Да се симулира целосниот животен циклус на корисник и неговите
ресурси, вклучувајќи тестирање на каскадното бришење.

### Синџир (11 чекори):

1. **Чекор 1** — Регистрирање на корисник
2. **Чекор 2** — Создавање рецепт
3. **Чекор 3** — Создавање листа за купување
4. **Чекор 4** — Додавање ставка во листата
5. **Чекор 5** — Создавање коментар на рецептот
6. **Чекор 6** — Верификација дека **сите** ресурси постојат (паралелни GET)
7. **Чекор 7** — Бришење на рецептот
8. **Чекор 8** — Рецептот е 404; коментарот исто → **каскадно бришење**
9. **Чекор 9** — Бришење на листата за купување
10. **Чекор 10** — Admin го брише корисникот
11. **Чекор 11** — Корисникот е 404; старата сесија е неважечка

**Клучна проверка:** Каскадното бришење (рецепт → коментари) и
орфан-ресурс однесување при бришење на корисник.

**Инспирација:** GoRest "Chained Testing" и "Cascading Deletions"

## Технички Детали

### Поставување на Тестовото Опкружување

```bash
# Во tests/e2e/ директориумот:
yarn install

# Стартување на Mealie backend (порт 9000):
docker compose up

# Извршување на сите API тестови:
npx playwright test api_testing/ --reporter=html

# Само една група:
npx playwright test api_testing/test_01_authentication.spec.ts
```

### Зошто Playwright (не Postman)?

| Аспект | Postman | Playwright |
|--------|---------|------------|
| Јазик | JavaScript (script) | TypeScript (type-safe) |
| Интеграција | GUI апликација | CI/CD pipeline |
| Синџирање | Преку pm.environment.set | `let` променливи + `serial` |
| Cleanup | Рачно | beforeAll/afterAll хуци |
| Верификација | pm.test() | expect() assertions |
| Паралелизам | Ограничен | Вграден |

### api_helpers.ts — Споделени Функции

| Функција | Опис |
|----------|------|
| `randomString(n)` | Генерира случаен стринг со должина n |
| `randomEmail()` | Генерира уникатна тест е-пошта |
| `getToken(req, email, pass)` | Добива Bearer токен |
| `getAdminToken(req)` | Кратенка за admin токен |
| `getSelf(req, token)` | Го добива сопствениот профил |
| `authHeader(token)` | Гради `{ Authorization: "Bearer ..." }` |
| `registerAndLogin(req, opts)` | Регистрира + логира нов корисник |
| `createRecipe(req, token, name)` | Создава рецепт, враќа slug |
| `deleteRecipe(req, token, slug)` | Брише рецепт (за cleanup) |
